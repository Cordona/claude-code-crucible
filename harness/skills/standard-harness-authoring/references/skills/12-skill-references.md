# 12 · References (REF)

Purpose: each reference file is read exactly when its branch arises, and no rule a run must obey depends on it being read.
Judges what moves out of `SKILL.md`, its trigger, its stub, the reading chain, its citers and the must-survive backstop; sizes, orphans, link targets, contents lists, condition words and duplicate fragments are lint.

**Applies when:** a skill or command file bundles a reference file: any `.md` in the skill dir other than `SKILL.md`, outside `evals/**`. N/A when there is none, and for agent files.
**MUST lint:** LNT-30. SHOULD lint used here: LNT-15, LNT-16, LNT-17, LNT-18, LNT-19, LNT-77, LNT-78.

**Levels.** Each item takes the level of the heading above it.

## MUST

- **REF-03** · Does the test that decides whether a branch applies stay in the body, with only the handling moved to the reference? · Check: for each reference, find what sends the reader there; FAIL when that test (which exit, which field, which reply shape) is stated only in the reference, so the reader must read the file to learn whether it needs it. · Fix: state the test in the body's step or stub; keep the handling in the reference.
- **REF-06** · Does every gate, stop, consent or untrusted-data rule found in a reference also stand in the body's Never or Always (STR-03 places it there)? A reference read before a compaction is not re-attached after it. · Check: read each reference for gates, stops, consent and untrusted-data rules; FAIL each that no body Never or Always line covers. · Fix: add the rule to Never (a prohibition) or Always (a requirement); in the reference keep only the handling, pointing to that line (REF-07).

## SHOULD

- **REF-01** · Does every pointer to a bundled file say what the file holds and name a condition the reader can see at that moment (an exit code, a reply shape, the human's ask, an input kind), never "for details", with a verb that says whether the file is run (a script) or read (a reference)? · Check: judge beyond LNT-77 (a condition word, or a lead clause closed by a colon, on the line), LNT-17 (a file named nowhere) and LNT-30 (a path that doesn't exist): FAIL a condition the reader can't observe at that step, and a trigger that fires on an absence ("no hook message") unless a body Never or Always line backs the same case. · Fix: name the file, what it holds and the observable condition ("On exit 3 or 6, read `reply-failures.md` for the resend rules"); "run" a script, "read" a reference; back an absence trigger with a Never or Always line.
- **REF-02** · Is each pointer at the step where its trigger arises, with a closing list or Dependencies section holding only triggers no step owns? · Check: judge per trigger, not per file: FAIL a pointer whose trigger arises at a step but sits away from it. A closing-list or Dependencies entry passes for a trigger no step owns (a dependency missing, the human asking to turn something off), even when a step also points to the same file. · Fix: move the pointer into the step where its trigger arises; keep a closing-list or Dependencies entry only for a trigger no step owns.
- **REF-04** · Does the body hold what every typical run needs, with branch, variant and edge detail in references — except in an agent-preloaded skill, where a reference is used only if the reading agent is shown to resolve its path? · Check: judge placement only; size is LNT-15/16, and their waiver waives size here. FAIL a reference read on most typical runs (move it into the body), and branch or edge detail in the body that a typical run never walks. · Context: `grep -rl '<name>' <agents dir>` for `skills:` preloads. · Fix: move every-run text into the body and branch detail to a reference pointed to at its step; in a preloaded skill keep it in the body and waive LNT-15; re-point every citer (REF-10).
- **REF-05** · Does each reference serve one domain, one family of cases (one failure family, one kind of human ask, one variant), never a grab-bag of unrelated cases? · Check: one domain is the test: PASS a file whose sections serve one family, even when its triggers fire at different steps; FAIL only a file that mixes unrelated families, so a reader sent for one reads text that never applies to its case. · Fix: split it by family, one pointer each.
- **REF-07** · Is each moved or promoted rule stated once, the other place pointing to it, never restating it? · Check: judge beyond LNT-78 (a sentence of 8+ words or a fragment of 10+ shared with a reference): FAIL a restatement in other words between the body and a reference; a copy in another skill is STR-05's. · Fix: keep the rule in one place (a must-survive rule in Never or Always) and replace the other copy with a pointer.
- **REF-08** · Does a moved numbered step or named section keep its number or heading as a one-line stub holding the trigger, shorter than the text it replaced? · Check: FAIL a moved step whose number or heading is gone, a stub with no trigger, and a stub as long as the text it replaced. · Context: the change's diff (`diff.patch`, or the pre-change files) when the brief gives one; with none, judge the stubs on the current files (each moved step or heading still present as one line holding a trigger), never `UNDECIDABLE`. · Fix: restore the number or heading as one line: the condition and the file it sends the reader to.
- **REF-09** · Is everything a required step needs reachable in one hop from `SKILL.md` — a reference never sends the reader to another reference, a hop into another skill's reference names that skill's file and heading directly, and no pointer lands on a stub? · Check: judge beyond LNT-18 (it counts only named links between the skill's own references): FAIL an indirect hop, a reference that reaches another reference without naming it ("as that step's reference sets"); a hop into another skill that names only its body; and a pointer ("as step 10 sets") that lands on a stub. · Context: the files and headings of the cited skills. · Fix: point straight at the file and heading that hold the text.
- **REF-10** · Does every citer of moved text (the skill's own pointers, other skills, audit checklists, script `--help` pages and comments) name the new file and heading, never a line number? · Check: judge beyond LNT-46 (`§N` citations): FAIL each citer that still names the old step, heading or a line number. · Context: the change's diff (`diff.patch`, or the pre-change files) when the brief gives one, for the old step numbers, headings and phrases; with none, the current files. Then `grep -rn` the moved step's number, its heading and up to five distinctive phrases across the search roots and `~/.claude/CLAUDE.md`. · Fix: re-point each citer to the new file and heading in the same change.
