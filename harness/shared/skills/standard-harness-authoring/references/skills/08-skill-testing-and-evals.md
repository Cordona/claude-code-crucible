# 08 · Testing and evals (EVAL)

Purpose: evidence shows the skill triggers when it should and improves the output.
Judges eval design, grading discipline and iteration; eval file format and counts are lint.

**Applies when:** every skill at creation and at each substantive change. Flows: N/A. EVAL-08 only for model-invocable skills; EVAL-11 only with `claude plugin eval`.
**MUST lint:** LNT-00, LNT-38.

- **EVAL-01** · SHOULD · Were the evals written from gaps seen in a no-skill baseline run before the skill was written out — for a refactor, from the previous version as baseline? · Check: yes if each case cites the gap it tests; "written before" is N/A for a refactor. · Fix: run the task without the skill (or with the old version), record failures, write one case per failure.
- **EVAL-02** · SHOULD · Does each output case use a realistic prompt as the requester would type it (not naming the skill), varied in phrasing, detail and formality, with every input seeded and at least one edge case in the set? · Check: read `evals/`. · Fix: rewrite prompts in user voice; vary them; add fixtures and an edge case.
- **EVAL-03** · SHOULD · Is each case run with and without the skill (or against the previous version) from a fresh session, the baseline disabling the skill via `skillOverrides: "off"` or an absent symlink (recorded), and judged by the delta? · Check: read the run record. · Fix: add the baseline arm, record how the skill was disabled, report Δ.
- **EVAL-04** · SHOULD · Are assertions added after the first run, objective and not brittle, mechanical ones scripted, and reviewed — always-pass-both removed, always-fail investigated, wrong-output-would-pass rewritten, unchecked outcomes added, skill-makes-worse treated as a skill defect? · Check: read assertions and the last benchmark. · Fix: rewrite vague assertions as countable checks; delete non-discriminating ones.
- **EVAL-05** · SHOULD · Does a PASS need quoted evidence from the actual output files, uncertainty grade FAIL with no partial credit, and does the grader also check the output's own claims and the executor's notes of workarounds? · Check: read the grading instructions. · Fix: require an evidence quote per PASS; add the claims and notes steps; have the executor brief ask for uncertainties and workarounds in `user_notes.md`.
- **EVAL-06** · SHOULD · Are conclusions drawn from at least three runs per arm, with duration and tokens recorded per run, and high variance answered by tighter instructions? · Check: read the benchmark; token figures are measurement only and never shown in flow gates or plans. · Fix: rerun at 3 runs per arm; record duration and tokens per run.
- **EVAL-07** · SHOULD · Is triggering measured separately from output quality, by a natural prompt and by `/name`? · Check: read. · Fix: add both trigger checks per case.
- **EVAL-08** · SHOULD · Is the description tuned on a trigger set with (a) substantive multi-step queries, (b) near-miss negatives and sibling-competition positives, (c) ≥ 3 runs per query against a 0.5 rate with errored runs excluded, (d) a class-stratified split whose held-out scores the proposer never sees, selection by validation and fresh confirmation queries, (e) the set reviewed by the human, (f) only after the body was stable? · Check: report FAIL(a–f). · Fix: build the set (LNT-39); run the loop; recheck LNT-09 each round.
- **EVAL-09** · SHOULD · Was the skill tested on the models it runs on with that tier's question (Haiku: enough guidance? Sonnet: clear and efficient? Opus-tier: no over-explaining?), and after a model change re-run with an arm whose prescriptive guidance is trimmed, keeping the trim if Δ ≥ 0? · Check: read the run record's model field. · Fix: rerun on the session model; add the trimmed arm.
- **EVAL-10** · SHOULD · Were real-use traces read for navigation problems (unread files, repeated reads, wasted steps, never-invoked skills) and the fixes generalized? · Check: read the iteration notes. · Fix: read two real transcripts and act on each problem.
- **EVAL-11** · MUST · With `claude plugin eval`, are all dependencies (agents, skills, hooks) shipped in the plugin, tools and mocks granted, graders on both result and steps (including Skill-fired and must-not-fire cases), CI flags pinned, and scores treated as advisory when foreign hooks run? · Check: N/A with another runner. · Fix: bundle the dependencies; add the graders and flags.
- **EVAL-12** · SHOULD · Does each iteration put outputs in front of the human before the author judges them, re-run all cases and baselines into its own record, record feedback, optionally add a blind A/B, and stop on empty feedback or a plateau? · Check: read the iteration records. · Fix: show outputs first; rerun everything; record feedback and the stop reason.
