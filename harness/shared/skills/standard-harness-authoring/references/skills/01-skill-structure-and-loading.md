# 01 · Structure and loading (STR)

Purpose: the skill loads cheaply and the agent finds what it needs at the step that needs it.
Judges layout, progressive disclosure and what survives compaction; sizes, links and citations are lint.

**Applies when:** every skill and command file. Agent files: STR-05 and STR-06 only (via the agent checklists).
**MUST lint:** LNT-01, LNT-20, LNT-25, LNT-30, LNT-46. SHOULD lint used here: LNT-15, LNT-16, LNT-18, LNT-19, LNT-51.
**Restructuring:** every Fix that moves, merges or renumbers a section follows the restructuring invariant in `SKILL.md` (LNT-46).

- **STR-01** · SHOULD · Is the skill one job — every section serves the same trigger and outcome — with SKILL.md as the overview that routes to detail? · Check: yes if no section would make sense as a separate skill with its own trigger. · Fix: split the second job into its own skill and update every citer; or cut it.
- **STR-02** · SHOULD · Does the body hold only what every invocation needs, with branch- or domain-specific detail in reference files — except in an agent-preloaded skill, where a reference is used only if the reading agent is shown to resolve its path? · Check: judge placement only; size is LNT-15/16, and their waiver waives size here. · Context: `grep -rl '<name>' <agents dir>` for `skills:` preloads. · Fix: move branch detail to `references/<topic>.md` pointed to at its step; in a preloaded skill keep it and waive LNT-15; update every citer of a moved section (LNT-46).
- **STR-03** · MUST · Are the must-survive rules (invariants, gates, stop conditions, consent and untrusted-data rules) within the part of the body that compaction keeps (LNT-25's limit), and written as standing rules? · Check: LNT-25 places the Invariants section; locate each gate, stop condition, consent and untrusted-data rule outside it yourself, against the same limit. · Fix: move them to an early Invariants section — move, never delete — rephrase as standing ("after every edit…"), and update every citer of a moved section (LNT-46).
- **STR-04** · SHOULD · Does SKILL.md say, for every bundled file, what it holds and when to load or run it? · Check: yes if each mention has a trigger ("read X when …"); "see references/" alone is no. · Fix: add one line per file: purpose + the step or condition that loads it.
- **STR-05** · SHOULD · Is each fact stated once, in its owning skill, and cited (skill + §) elsewhere, with any kept restatement carrying a one-line reason? · Check: yes if no unreasoned restatement is found. · Context: `grep -rn` up to five distinctive phrases of the target across the collection and `~/.claude/CLAUDE.md`. · Fix: replace the copy with a citation, or add the reason the copy must stay.
- **STR-06** · SHOULD · When the skill depends on another skill or file, does it say whether to load it and when, with every chain one level deep from SKILL.md? · Check: yes if acting never needs A → B → C (LNT-18 checks file links). · Context: headings of the cited skills. · Fix: link the deep file from SKILL.md, or cite the owning skill's § and say to load it; never paste a copy (STR-05).
- **STR-07** · SHOULD · Are names descriptive and directories split by role (`scripts/`, `references/`, `assets/`, `examples/`, `lib/`)? · Check: yes if a name alone tells what a file holds (LNT-22 flags generic names). · Fix: rename to `<topic>-<kind>`; move under the role directory and update every reference.
- **STR-08** · SHOULD · Is every example the skill ships — `examples/`, `assets/` templates, runnable code blocks — complete and consistent with the current scripts, flags and paths? · Check: judge by reading only; parsing is LNT-51; yes if fragments are labelled illustrative. · Fix: repair or delete it; label fragments.
