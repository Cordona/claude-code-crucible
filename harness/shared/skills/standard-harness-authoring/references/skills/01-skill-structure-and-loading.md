# 01 · Structure and loading (STR)

Purpose: the skill does one job, in files and sections laid out in the order the reader uses them, and its must-survive rules outlast compaction.
Judges scope, layout, section order and what survives compaction; citations are lint.

**Applies when:** every skill and command file. Agent files: STR-05, STR-06 and STR-09 only (via the agent checklists).
**MUST lint:** LNT-01, LNT-20, LNT-25, LNT-46. SHOULD lint used here: LNT-51.
**Restructuring:** every Fix that moves, merges or renumbers a section follows the restructuring rule in `SKILL.md` (Always; LNT-46).

- **STR-01** · SHOULD · Is the skill one job — every section serves the same trigger and outcome? · Check: yes if no section would make sense as a separate skill with its own trigger. · Fix: split the second job into its own skill and update every citer; or cut it.
- **STR-03** · MUST · Are the must-survive rules (gates, stop conditions, consent and untrusted-data rules) within the part of the body that compaction keeps (LNT-25's limit), and written as standing rules in early `## Never` and `## Always` sections — a prohibition in Never, a requirement in Always — with an `## Invariants` section only for a must-survive rule that is neither? · Check: LNT-25 places the Never, Always and Invariants sections; FAIL a prohibition outside Never, a requirement outside Always, and an Invariants rule that is either; locate each gate, stop condition, consent and untrusted-data rule outside these sections yourself, against the same limit. · Fix: move each to Never (a prohibition), Always (a requirement) or, only when it is neither, Invariants — move, never delete — rephrase as standing ("after every edit…"), and update every citer of a moved section (LNT-46).
- **STR-05** · SHOULD · Is each fact stated once, in its owning skill, and cited (skill + §) elsewhere, with any kept restatement carrying a one-line reason? · Check: yes if no unreasoned restatement is found. · Context: `grep -rn` up to five distinctive phrases of the target across the collection and `~/.claude/CLAUDE.md`. · Fix: replace the copy with a citation, or add the reason the copy must stay.
- **STR-06** · SHOULD · When the skill depends on another skill (for an agent file, also a file it reads), does it say whether to load it and when? · Check: yes if each dependency names when it is loaded, or that it is not. · Context: headings of the cited skills. · Fix: cite the owning skill's § and say when to load it; never paste a copy (STR-05).
- **STR-07** · SHOULD · Are names descriptive and directories split by role (`scripts/`, `references/`, `assets/`, `examples/`, `lib/`)? · Check: yes if a name alone tells what a file holds (LNT-22 flags generic names). · Fix: rename to `<topic>-<kind>`; move under the role directory and update every reference.
- **STR-08** · SHOULD · Is every example the skill ships — `examples/`, `assets/` templates, runnable code blocks — complete and consistent with the current scripts, flags and paths? · Check: judge by reading only; parsing is LNT-51; yes if fragments are labelled illustrative. · Fix: repair or delete it; label fragments.
- **STR-09** · SHOULD · Are the sections in the order the reader uses them: what it acts on first, then what it consults while acting, then reference material last? · Check: take the target's kind and its row from `SKILL.md` "Reading order by kind"; confirm the reader's first action from the target itself (a flow's step 1, an agent's dispatch check), and where it differs from the row, that action leads and the rest of the row follows. FAIL each section out of the row's order, and each reference section the row doesn't name (a lookup table, background) that sits above the first step that consults it, unless the target gives a one-line reason. · Context: `SKILL.md` "Which checklists apply" and "Reading order by kind". · Fix: move the section to its place in the expected order, or add the one-line reason it must sit higher.
