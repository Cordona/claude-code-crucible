# agent-03 · Context and load (ALOAD)

Purpose: the agent assumes only what a subagent actually gets, loads only what it uses, and stays within its load budget.

**Applies when:** every agent file. ALOAD-01 is N/A for an orchestrator-only agent. This seat also judges 02, STR-05 (a procedure pasted from a skill instead of cited), STR-06 (the skills and files the agent reads on demand) and STR-09 (section order, against the Agent file row of the rulebook's "Reading order by kind").
**MUST lint:** LNT-36, LNT-73. SHOULD lint used here: LNT-62, LNT-68, LNT-69, LNT-70.
**Terms.** See `README.md` (the agent's text, waivers file).

- **ALOAD-01** · MUST · Does the agent's text never assume context a subagent doesn't get: the conversation, files the caller read, earlier dispatches, the caller's skills, auto memory? A subagent gets only its body, the brief, CLAUDE.md (unless omitted), a git-status snapshot and its preloads. · Check: grep for "as discussed", "the user said", "earlier", "the conversation", "you already"; read the inputs. · Fix: name the brief field or file that carries it.
- **ALOAD-02** · SHOULD · Is `omitClaudeMd: true` set when the agent takes everything from its dispatch? Otherwise the operating-contract `CLAUDE.md` loads into every dispatch. (Managed-policy files still load; the field is ignored when the agent runs as the main session; its minimum Claude Code version is in the frontmatter-fields Versions table.) · Check: lint LNT-62; a waiver saying why the agent needs CLAUDE.md passes. · Fix: add `omitClaudeMd: true`.
- **ALOAD-03** · MUST · Does every `skills:` entry resolve to a skill in the collection? · Check: lint LNT-36. · Fix: correct the name or remove the entry.
- **ALOAD-04** · MUST · Is no `skills:` entry a skill with `disable-model-invocation: true`? Such a preload is skipped with only a debug warning. · Check: read each preloaded skill's frontmatter. · Fix: remove the flag from the skill (FM-06); remove the entry from the agent only when the skill must stay a user-typed command nothing binds.
- **ALOAD-05** · SHOULD · Is every `skills:` preload used by a step on most dispatches? Each loads its full body every time. · Check: for each preload, find the step that uses it. · Context: the preloaded skills' sizes (`wc -c`). · Fix: turn a rarely used preload into an on-demand read (ALOAD-06).
- **ALOAD-06** · SHOULD · Does each on-demand skill read give an exact path and its trigger ("read `$HOME/.claude/skills/<name>/SKILL.md` when …"), used only when the agent has Bash or `$HOME` resolution for Read has been verified? A gate procedure is never made on-demand. · Check: read each on-demand reference. · Fix: write the full path and the trigger, or keep it as a preload.
- **ALOAD-07** · SHOULD · If the body tells the agent to invoke a skill through the Skill tool, is `Skill` in `tools`? Without it, all skill use is blocked. · Check: grep the body for skill invocations. · Fix: add `Skill`; preload the skill instead only when a step uses it on most dispatches (ALOAD-05).
- **ALOAD-08** · SHOULD · Does each part of the load per dispatch earn its place: the body, and the body plus its preloads? · Check: sizes are lint LNT-68 and LNT-69, and CLAUDE.md is LNT-62; judge only whether a section or preload could be cited or deferred instead. When LNT-68 or LNT-69 is waived, still judge that cite-or-defer part and report PASS or FAIL, never WAIVED. · Fix: cut or defer preloads; cite instead of restating.
- **ALOAD-09** · SHOULD · Is every rule the agent shares with another file (a dispatch template, a sibling agent, a workflow constant) kept in one place and cited, or kept byte-identical by a lint (as LNT-60 does for the canonical blocks)? Copies drift. · Check: grep a distinctive phrase of each key rule across flows and agents. · Fix: cite the one source, or add the copy to a lint.
- **ALOAD-10** · SHOULD · If the agent reads files that may exceed the Read limit (frontmatter-fields Versions table), does the body say to read them in parts with `offset` and `limit`? · Check: read the inputs; N/A when they are small by construction. · Fix: add the read-in-parts rule.
- **ALOAD-11** · SHOULD · If `memory` is set (it does nothing while auto memory is off), does the body say to consult memory before the work and update it after? · Check: read; N/A without `memory`. · Fix: add both steps.
- **ALOAD-12** · SHOULD · If the agent keeps notes across dispatches, does the body name the notes file, say to read it first and rewrite it last, and cap its size? · Check: read; N/A when it keeps none. · Fix: add the file, the read-first and rewrite-last steps, and a word cap.
