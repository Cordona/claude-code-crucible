# GitHub PR review-feedback response shapes

Scrubbed, shape-only samples of real GitHub REST and GraphQL responses about pull-request review feedback. Keys, nesting, array lengths (except `topics[]`), nulls, booleans, value types and enum values are real; every other value is synthetic.

Each `.json` file is the pure response body. A sibling `.headers.txt` holds the status line and allowlisted headers. REST calls used API version 2022-11-28 (see `x-github-api-version-selected`).

## Observations worth knowing

- `in_reply_to_id` is an optional key on review comments: it is present only on replies and absent (not null) otherwise.
- Outdated review comments keep `position` (often 1) and `original_line`, while `line` is null.
- Copilot appears as login `Copilot` (type Bot, no `[bot]` suffix) on review comments, but as `copilot-pull-request-reviewer[bot]` on review objects and `copilot-pull-request-reviewer` (no suffix) as a GraphQL Bot author.
- GraphQL Bot logins never carry the `[bot]` suffix; REST App logins do.
- Review comments and reviews carry undocumented `is_copilot_code_review`, `copilot_code_review_severity` (low/medium/high/null), `copilot_code_review_effort` (balanced/null) and `copilot_code_review_sources` (array of `{kind, name}`) fields.
- Media types differ by endpoint: on issue comments `.text+json` returns `body_text` INSTEAD of `body` and `.html+json` returns `body_html` INSTEAD of `body`; on review comments `.text+json`/`.html+json` ADD `body_text`/`body_html` and keep `body`. `.full+json` returns all three on both. `.raw+json`, the default and the Accept-less call return `body` only. `x-github-media-type` echoes the param (`github.v3; param=html; format=json`).
- `sort=bogus` and `direction=bogus` on `GET /repos/{owner}/{repo}/pulls/comments` were silently ignored (HTTP 200, normal list), so no 422 sample exists for them; `since=bogus` returns 422.
- GraphQL NOT_FOUND is returned with HTTP 200, `data.repository.pullRequest: null` and an `errors[]` entry.
- The 304 response has no body and still counts toward rate-limit headers.

## Variants not found in the sampled organization

- Review state PENDING: none visible (only the viewer's own pending review would be listed).
- Review or comment with `user: null` / `ghost` (deleted user): none found.
- Account type Organization as a comment/review author: none (Organization appears only as repository owner).
- `author_association` OWNER, COLLABORATOR, FIRST_TIME_CONTRIBUTOR, FIRST_TIMER, MANNEQUIN: none; seen were MEMBER, NONE, CONTRIBUTOR.
- LEFT side (`side`/`start_side`/`diffSide` LEFT): none; all sampled comments and threads are RIGHT.
- File-level comment (`subject_type: "file"`, GraphQL `subjectType: FILE`): none.
- Minimized (hidden) comment (`isMinimized: true`, `minimizedReason` set): none.
- GraphQL review thread started by a custom GitHub App bot: none; the bot-author thread sample is started by the Copilot reviewer.
- Review comment with `pull_request_review_id: null`: none (every sampled comment belongs to a review).
- A reply by someone other than the PR author: none in the sampled PRs (only PR-author replies).
- Copilot as a conversation (issue) comment author with no `[bot]` suffix: seen in discovery but not sampled as its own file.
- A check-run with conclusion `action_required`: the sampled head's check-runs were already `success`.

## Not collected (write endpoint, not reproduced)

- `POST /repos/{owner}/{repo}/pulls/{n}/reviews` (approve) returning 422 when the head moved: this is a write, so it was not reproduced.

## How these were scrubbed

- Allowlist approach: a string value is kept only if it is an enum or format value on the allowlist (review/PR state, author_association, side/start_side/diffSide, subject_type, user/author `type`, GraphQL `__typename`, reaction `content`, minimizedReason, mergeable_state, pull_request_creation_policy, check-run status/conclusion, App permission levels and event names, Copilot severity/effort/source kind, header names, media-type strings) or a generic public GitHub login (github-actions[bot], Copilot, copilot-pull-request-reviewer[bot]). The owner object of GitHub's own public Actions app is kept as returned.
- Keys, key order, nesting, nulls, booleans and types are unchanged, and array lengths are preserved except `topics[]` (trimmed to one item); a structural diff against each source confirmed identical key paths and types.
- Numeric ids map to small fake ids consistently across all files, so `in_reply_to_id`, `pull_request_review_id`, GraphQL `databaseId` and URL ids stay coherent. PR numbers map to small fake numbers.
