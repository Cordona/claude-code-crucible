# Resume: the effort's seats after a break

Its terms and steps are SKILL.md's.

1. **The context:** load `procedure-context` with the Skill tool, with the effort folder, and take the `CONTEXT_DOCS:` or `CONTEXT_FILE:` line it hands back; nothing below runs until it hands one over. Once it does, come back here; never split again a part that has a seat in the seat list, chosen or later (SKILL.md 2.4); a dropped seat no longer counts.
2. **The seats,** read only through the scripts: never run `events.sh` or read `events/`, but for an event file a script hands over by path (`iteration.sh`'s `LAST_REPORT:`). Run `list=$(sh "<scripts>/seats/seats.sh" list --effort '<effort folder>') && printf '%s\n' "$list" | jq -r '.seats[] | [.seat, .status, .worktree] | @tsv'`. No seats: none is held (none was chosen, or every one was dropped): go on from SKILL.md step 2. A seat's part is its task, from this session's todo item (`<seat>: …`) or the conversation (no script reads a dispatch's task); when neither holds it, step 3 says what to do. Never run `git` in a worktree or the checkout to learn a part; ask the human instead. When a read fails, show its output and record `not checked` for each seat it leaves unknown.
3. **One state per seat,** by its status:
   - **`chosen`:** a plan never answered. When this session still holds its part (its todo item `<seat>: <task>` or the conversation, as after a compaction), take that part through SKILL.md step 2.5 with that seat; when it can't tell: show the line `part_not_done`, with `--arg task '<seat>'` and `--arg why 'plan never answered'`, then offer to drop it: load `procedure-approval-gate` with the Skill tool and follow its steps, one such seat at a time, with these inputs:
     - **The plan file:** `{"seat": "<seat>"}`, written with the Write tool.
     - **The renderer:** `<show.sh> render --views <views> --name drop-seat < '<the plan file>'`.
     - **The gate's label:** `seat-drop`, with `--effort '<effort folder>'`.
     - **Above the gate:** the line `part_not_done`, with the other cards shown this turn.
     - **On "now ask":** Read `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/flow-code-development/references/drop-question.json` and pass its `questions` to one AskUserQuestion as written.
     - **The answer:** `Drop it (Recommended)` → `sh "<scripts>/seats/seats.sh" drop --effort '<effort folder>' --seat '<seat>'`; a refusal: show its stderr and leave the seat. `Keep it`: leave the seat. A typed answer: open the gate again.
     - **The gate can't be shown or asked:** show the human what failed, and leave the seat.
   - **`open`:** never launched (a denial, or a break before the call): take its part through SKILL.md step 2.5 again when step 2 found its task; otherwise show the line `part_not_done`, with `--arg task '<seat>'` and `--arg why 'task unknown'`, and ask the human for its task; on an answer, take it through SKILL.md step 2.5 with that seat; otherwise leave it.
   - **`working`:** its todo item records `not committed`, or no send since its last result: SKILL.md step 4's `working` line, here `procedure-git-worktree`'s line `run_not_committed` shown with `--arg seat '<seat>'` and `--arg worktree '<worktree>'`. Otherwise, after a compaction in the same session, its run may still end: wait for it (SKILL.md step 4). In a new session, or when you can't tell, ask the human whether its agent may still run: "it may" records it `not checked`; "it doesn't": that same line, its run ended.
   - **`idle`:** run `sh "<scripts>/seats/iteration.sh" --effort '<effort folder>' --seat '<seat>' --checked '<task>'`, `<task>` the seat's name when step 2 found none: its line `checked_earlier` says done or blocked by SKILL.md Terms' done test; a non-zero exit: show its stderr, and record `not checked`. Its card only when the human asks.
   - **`gave-up`:** SKILL.md step 4's `gave-up` line, here `procedure-git-worktree`'s line `report_gave_up` shown with `--arg seat '<seat>'` and `--arg worktree '<worktree>'`.
4. **Parts with no seat:** a part the conversation still shows `waiting for <task>` goes on once that part is done (SKILL.md 2.4); in a new session the human may name such parts (SKILL.md Terms, a part's record).
5. **Then** go on from SKILL.md step 5.
