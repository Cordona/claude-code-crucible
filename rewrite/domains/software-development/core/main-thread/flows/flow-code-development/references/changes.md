# Changes: a change to a part already shown

A change the human asks for to a part already shown (a fix, a refactor, an addition to the same area and repository) goes to the same developer, still warm, over SendMessage; never back through step 2. Its terms are SKILL.md's, and what a change message and each `--note` line may carry unfenced is SKILL.md's Always. A step number alone is this file's; SKILL.md's steps are named so.

Copy steps 1–5 into the todo list and tick each.

1. **A changed contract first:** when the change alters the approved spec's goal, done-when or scope, run `procedure-context`'s The spec alone with the change. The human kept the spec as it is, or anything but a `CONTEXT_DOCS:` or `CONTEXT_FILE:` line back: send nothing (SKILL.md Always, Send nowhere). Then run SKILL.md 2.1's `context.sh spec --status`: anything but `SPEC: approved` with a `SPEC_FILE:` line: the same. A newly approved spec: from then on, every change to any seat names that `SPEC_FILE:` path and says it replaces the earlier one as the contract (step 3).
2. **The seat:** `idle`, `gave-up`, or `working` with its run ended (SKILL.md step 4 recorded it `not committed`); a run that may still go on: wait (SKILL.md Never). Unless it is already `working`, run `sh "<scripts>/seats/seats.sh" status --effort '<effort folder>' --seat '<seat>' --status working`; a non-zero exit: send nothing (SKILL.md Always, Send nowhere).
3. **Send:** run `sh "<scripts>/seats/iteration.sh" --effort '<effort folder>' --seat '<seat>'` for this iteration's `REPORT:` path; a non-zero exit: send nothing (SKILL.md Always, Send nowhere). Each new outside path or link the human gave with the change goes through `procedure-context`'s `extend.md` (and its `tracker-links.md` for a tracker link) first. Load SendMessage with ToolSearch, then send the seat's agent ID the change in the human's words, plus each such absolute path or link (its pinned context doesn't hold it, so it reads them now), step 1's spec line, the sync line its todo item holds from `procedure-git-worktree`'s `chains.md` (first, when there is one, then dropped from the item), and the line `REPORT: <that path>`. Show the line `The developer in <seat> is working on the change you asked for.`
4. **Its result:** SKILL.md step 4, then SKILL.md step 5 for this change alone.
5. **Unreachable** (the agent ID is not in the conversation or the todo list, or SendMessage fails): run `sh "<scripts>/seats/seats.sh" handover --effort '<effort folder>' --seat '<seat>'`, then `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/flow-code-agent-dispatch/scripts/agent-dispatch/generate-agent-dispatch.sh" --effort '<effort folder>' --seat '<seat>' --reseat` with one `--note '<line>'` per line: the change in the human's words, step 1's spec line, step 3's new paths and links, then its todo item's sync line, if any (then dropped from the item); each `--note` value single-quoted, each `'` as `'\''`. No plan, no gate, no re-run of SKILL.md step 2.5. Exit 0 with its `DISPATCH:`, `LABELS:` and `TITLE:` lines: SKILL.md step 3's Agent call with them, then SKILL.md step 4. A non-zero exit of either script, or any other result: send nothing (SKILL.md Always, Send nowhere).
