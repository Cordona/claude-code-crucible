# Changes: a change to a part already shown

A change the human asks for to a part already shown (a fix, a refactor, an addition to the same area and repository) goes to the seat's same agent, still warm, over SendMessage; never back through the caller's plan step. Its terms are SKILL.md's, and what a change message and each `--note` line may carry unfenced is SKILL.md's Always. A step number alone is this file's; SKILL.md's steps are named so. Each send fills the caller's slots (SKILL.md Interface).

Copy steps 1–5 into the todo list and tick each.

1. **A changed contract first:** when the change alters the approved spec's goal, done-when or scope, run `procedure-context`'s The spec alone with the change (load it with the Skill tool if it isn't in context). The human kept the spec as it is, or anything but a `CONTEXT_DOCS:` or `CONTEXT_FILE:` line back: send nothing (SKILL.md Always, Send nowhere). Then run `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/procedure-context/scripts/context.sh" spec --status --effort '<effort folder>'`: anything but `SPEC: approved` with a `SPEC_FILE:` line: the same. A newly approved spec: from then on, every change to any seat names that `SPEC_FILE:` path and says it replaces the earlier one as the contract (step 3).
2. **The seat:** `idle`, `gave-up`, or `working` with its run ended (SKILL.md Results recorded it `not committed`, its stop never recorded), taken as `gave-up` is, a tester's included; a run that may still go on: wait (SKILL.md Never). **The worktree check,** for a tester with no plan seq handed in (SKILL.md Interface; never a number read from a file name), its agent reachable or not, before any status change: run `git -C '<worktree>' status --porcelain` (`<worktree>` from `seats.sh get`; it only reads). Any output (its own uncommitted tests may be there): send nothing, change no status, and hand the seat back with the record `stopped: plan gate needed`: the caller asks its plan gate again and, on approval, comes back with the seq, so the agent continues those tests, never a plan over them. A non-zero exit: send nothing (SKILL.md Always, Send nowhere). Then, unless it is already `working`, run `sh "<seat scripts>/seats/seats.sh" status --effort '<effort folder>' --seat '<seat>' --status working`; an exit 5 naming the seat's pair: The pair hold, below; any other non-zero exit: send nothing (SKILL.md Always, Send nowhere).
   - **The pair hold** (one agent works in a worktree at a time): an exit 5 whose stderr names the seat's pair (`shares its worktree with seat "<pair>", which is working` or `…, which gave up`), here or at New work's `seats.sh task` (any other exit 5 is no pair refusal: Send nowhere); a part the caller hands in `stopped: pair busy` (its dispatch denied for the pair); or a seat the caller hands in with its pair `gave-up`. For each, `<pair>` comes from the seat list, never from stderr or a deny reason: a tester seat's `build_seat` in `seats.sh get`, or for a build seat the seat whose `build_seat` it is in `seats.sh list`. **The held step:** the held command again; with no held command (`stopped: pair busy`, a seat handed in), hand the seat back to the caller, which takes its step again. The pair working with its run not ended: wait for its result (SKILL.md Never), then the held step. Otherwise (it gave up, or its run ended uncommitted): hold the change or work, show the line `pair_leftovers`, with `--arg seat '<pair>'` and `--arg worktree '<worktree>'` (`<worktree>` from `seats.sh get`), then load `procedure-approval-gate` with the Skill tool and follow its steps, with these inputs:
     - **The plan file:** `{"seat": "<seat>", "pair": "<pair>", "worktree": "<worktree>"}`, written with the Write tool.
     - **The renderer:** `sh "<seat scripts>/render-pair-hold.sh" --plan-file '<the plan file>'`; act on each exit as its `--help` sets.
     - **The gate's label:** `pair-hold`, with `--effort '<effort folder>'`.
     - **Above the gate:** the line `pair_leftovers`.
     - **On "now ask":** run the renderer with `--question` added, and copy its `header`, `question` and `options` into one AskUserQuestion as they are.
     - **The gate can't be shown or asked:** show the human what failed, and send nothing (SKILL.md Always, Send nowhere).
     - **The answer,** matched to an option with `(Recommended)` ignored: `Resume the agent`: steps 2–4 on the pair's seat with the human's words (picked with none: ask in chat what it should do, then send), then the held step; those steps handing the pair back `stopped: plan gate needed`: the hold ends with no held step (running it again would loop): hand both seats back to the caller, the pair with that record and the held change or work recorded `held: pair busy`. `Discard (I cleaned the worktree)`: the human cleaned the worktree, never you; run `sh "<seat scripts>/seats/seats.sh" status --effort '<effort folder>' --seat '<pair>' --status idle`, then the held step. A typed answer: open the gate again, and send nothing until an option is picked.
3. **Send:** run `sh "<seat scripts>/seats/iteration.sh" --effort '<effort folder>' --seat '<seat>'` for the path the message's `REPORT:` line carries: a builder's message: its `REPORT:` path; a tester's: its `REPORT:` path only with a plan seq handed in (SKILL.md Interface; TEST, a fix round after a test report), else its `PLAN:` path (a new plan draft: a new plan, a change to its draft, or an agent resumed with no approved plan); a non-zero exit: send nothing (SKILL.md Always, Send nowhere). Each new outside path or link the human gave with the change goes through `procedure-context`'s `extend.md` (and its `tracker-links.md` for a tracker link) first. Load SendMessage with ToolSearch, then send the seat's agent ID the message text, plus each such absolute path or link (its pinned context doesn't hold it, so it reads them now), step 1's spec line, the sync line its todo item holds (first, when there is one, then dropped from the item), and the line `REPORT: <that path>`. Show the sent line, with `--arg seat '<seat>'`. **New work on the hot agent** sends the same way: the task in place of the change, its `REPORT:` line included, and the line `task_sent` shown in place of `change_sent`.
4. **Its result:** SKILL.md Results, then hand the seat back to the caller, which closes its run for this change alone.
5. **Unreachable** (the agent ID is not in the conversation or the todo list, or SendMessage fails): a tester with no plan seq reaches here only on a clean worktree (step 2's worktree check, or New work's): the re-seat is a PLAN one, with no `--test-plan`, so its dispatch hands the agent its `PLAN:` path and it plans again; its plan comes back through SKILL.md Results. Run `sh "<seat scripts>/seats/seats.sh" handover --effort '<effort folder>' --seat '<seat>'`, then `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/flow-code-agent-dispatch/scripts/agent-dispatch/generate-agent-dispatch.sh" --effort '<effort folder>' --seat '<seat>' --reseat` with one `--note '<line>'` per line: the re-seat note, step 1's spec line, step 3's new paths and links, then its todo item's sync line, if any (then dropped from the item). With a seq, it also takes `--test-plan '<seq>'`; its dispatch hands the agent the `REPORT:` path and that plan itself, so no message follows it. No plan, no gate, no re-run of the caller's plan step. Exit 0 with its `DISPATCH:`, `LABELS:`, `TITLE:` and `AGENT:` lines: SKILL.md Launch's Agent call with them, then SKILL.md Results. A non-zero exit of either script, or any other result: send nothing (SKILL.md Always, Send nowhere).
