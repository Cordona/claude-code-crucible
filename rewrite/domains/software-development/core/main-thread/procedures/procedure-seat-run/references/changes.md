# Changes: a change to a part already shown

A change the human asks for to a part already shown (a fix, a refactor, an addition to the same area and repository) goes to the same developer, still warm, over SendMessage; never back through the caller's plan step. Its terms are SKILL.md's, and what a change message and each `--note` line may carry unfenced is SKILL.md's Always. A step number alone is this file's; SKILL.md's steps are named so. Each send fills the caller's slots (SKILL.md Interface).

Copy steps 1–5 into the todo list and tick each.

1. **A changed contract first:** when the change alters the approved spec's goal, done-when or scope, run `procedure-context`'s The spec alone with the change (load it with the Skill tool if it isn't in context). The human kept the spec as it is, or anything but a `CONTEXT_DOCS:` or `CONTEXT_FILE:` line back: send nothing (SKILL.md Always, Send nowhere). Then run `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/procedure-context/scripts/context.sh" spec --status --effort '<effort folder>'`: anything but `SPEC: approved` with a `SPEC_FILE:` line: the same. A newly approved spec: from then on, every change to any seat names that `SPEC_FILE:` path and says it replaces the earlier one as the contract (step 3).
2. **The seat:** `idle`, `gave-up`, or `working` with its run ended (SKILL.md Results recorded it `not committed`); a run that may still go on: wait (SKILL.md Never). Unless it is already `working`, run `sh "<seat scripts>/seats/seats.sh" status --effort '<effort folder>' --seat '<seat>' --status working`; a non-zero exit: send nothing (SKILL.md Always, Send nowhere).
3. **Send:** run `sh "<seat scripts>/seats/iteration.sh" --effort '<effort folder>' --seat '<seat>'` for this iteration's `REPORT:` path; a non-zero exit: send nothing (SKILL.md Always, Send nowhere). Each new outside path or link the human gave with the change goes through `procedure-context`'s `extend.md` (and its `tracker-links.md` for a tracker link) first. Load SendMessage with ToolSearch, then send the seat's agent ID the message text, plus each such absolute path or link (its pinned context doesn't hold it, so it reads them now), step 1's spec line, the sync line its todo item holds (first, when there is one, then dropped from the item), and the line `REPORT: <that path>`. Show the sent line, with `--arg seat '<seat>'`. **New work on the hot agent** sends the same way: the task in place of the change, its `REPORT:` line included, and the line `task_sent` shown in place of `change_sent`.
4. **Its result:** SKILL.md Results, then hand the seat back to the caller, which closes its run for this change alone.
5. **Unreachable** (the agent ID is not in the conversation or the todo list, or SendMessage fails): run `sh "<seat scripts>/seats/seats.sh" handover --effort '<effort folder>' --seat '<seat>'`, then `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/flow-code-agent-dispatch/scripts/agent-dispatch/generate-agent-dispatch.sh" --effort '<effort folder>' --seat '<seat>' --reseat` with one `--note '<line>'` per line: the re-seat note, step 1's spec line, step 3's new paths and links, then its todo item's sync line, if any (then dropped from the item); each `--note` value single-quoted, each `'` as `'\''`. No plan, no gate, no re-run of the caller's plan step. Exit 0 with its `DISPATCH:`, `LABELS:`, `TITLE:` and `AGENT:` lines: SKILL.md Launch's Agent call with them, then SKILL.md Results. A non-zero exit of either script, or any other result: send nothing (SKILL.md Always, Send nowhere).
