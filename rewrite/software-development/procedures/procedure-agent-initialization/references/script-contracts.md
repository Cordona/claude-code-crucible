# Script contracts: the install check, the PLUGIN line and the hook

The full contracts of `scripts/check-install.sh`, `scripts/render-plugin-line.sh` and `scripts/inject-plugins.sh`. SKILL.md's Scripts section points here when a script's stdout, stderr or exit doesn't match what its step expects, or when a hook denial's reason needs explaining. `scripts/list-plugins.sh`'s contract is in the plugin layout, which SKILL.md's Scripts section points to. The skills folder below is `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/`.

## `scripts/check-install.sh` (the install check)

Run by the main thread at SKILL.md's step 1, every time the procedure starts.

- **Command:** `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/procedure-agent-initialization/scripts/check-install.sh" [--skills-dir DIR] [--settings FILE] [--cache-dir CACHE] [--force]`. `--force` skips the cache lookup and runs every check (a clean pass still writes the marker); `--cache-dir` sets the marker's folder, by default `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/cache/agent-init`; `--skills-dir` and `--settings` default to the skills folder and `settings.json`. The procedure passes none of them. `--help` (or `-h`) prints its contract.
- **Stdout, cached:** when the fingerprint matches the marker's, the header line and `✓ Install unchanged since <YYYY-MM-DD HH:MM>: <n> checks passed`, and exit 0.
- **Stdout, full:** otherwise a fixed checklist, one line per check: each of the three scripts (`list-plugins.sh`, `render-plugin-line.sh`, `inject-plugins.sh`), the `jq` version (1.6 or newer), the hook registered in `settings.json`, and the installed plugin count. A failed check prints `✗ <item>: <reason>. Fix: <action>`. Zero plugins installed is a `⚠ no plugins installed: …` warning, not a failure. The last line is `All checks passed.` (with ` (1 warning)` after a warning), `<n> check(s) failed: dispatch needs the hook; direct implementation can go on.` on exit 3, or `<n> check(s) failed.` on exit 1. The main thread shows either output to the user as is.
- **Exit codes:** 0 every check passed (a ⚠ warning included) or the cached pass still holds; 1 a script or plugin check failed, whatever else failed too; 2 a usage error; 3 only the `jq` or hook checks failed (a missing `jq` also fails the hook check; settings that aren't valid JSON fail the hook check): dispatch can't inject plugins, direct implementation can go on.
- **Every check runs** on a full run, whatever an earlier one found, so one run names every fix; it runs each script's `--help` and `list-plugins.sh --max-lines 0`.
- **The marker:** `CACHE/install-check`, three lines, `fingerprint <crc> <size>`, `passed YYYY-MM-DD HH:MM` and `checks <n>`, mode 600, holding no settings content. It is written (a temp file in the same folder, then `mv -f`) only after a clean full pass with no warning; a failed run or a warning removes it. A cache hit also needs a well-formed time and count, so a forged marker line gives a full run.
- **The fingerprint:** one `cksum` over a stream never stored or printed: the skills-folder and settings paths, the `cksum` of the four procedure scripts, the matching hook commands (`jq -c` output), the `jq --version` string, and each `tech-*` or `standard-*` folder's name with the `cksum` of its `SKILL.md` and `references/` files (symlinks followed). A step that fails adds a fixed line, so a missing file or tool changes the fingerprint instead of stopping the run. Not covered: a `settings.json` change outside the hook commands, and plugin files outside `SKILL.md` and `references/`; `--force` runs every check anyway. `cksum` is a CRC plus a length: change detection, not an integrity check, so anyone who can write the cache folder can forge a pass.
- **Cache errors** add `(result not cached: <reason>)` after the last line and never change the exit: `cksum not found on PATH`, `cksum failed`, `cannot create DIR`, `cannot write to DIR`, `date failed`, `cannot replace MARKER`, or a failed run's `the old result at … could not be removed`.
- **Dependencies:** POSIX `sh` and `tr`; `cksum`, `find`, `sort`, `date`, `mkdir`, `mktemp`, `mv` and `rm` for the cache; `jq` is a check, not a requirement.
- **Side effects:** it writes only the marker; it reads `settings.json` only through `jq`, counting or hashing the `PreToolUse` › `Agent` hook commands and never printing them.
- **Runtime:** about 0.12 s for a full pass of 8 plugins, 0.03 s cached; measured on macOS.

## `scripts/render-plugin-line.sh` (the PLUGIN line)

Run by the main thread at SKILL.md's steps 7, 9 and 10.

- **Command:** `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/procedure-agent-initialization/scripts/render-plugin-line.sh" --role developer|reviewer --mode BUILD|TEST [--labels] [--skills-dir DIR] [--] [NAME ...]`. `--skills-dir` defaults to the skills folder; the procedure never passes it. `--help` (or `-h`) prints its contract; no arguments prints usage and exits 2.
- **Does:** runs `list-plugins.sh --max-lines 0`, checks the names (each installed, at most one tech name, none twice, `standard-testing` on `TEST` and never on `BUILD`), then prints one line: `PLUGIN: ` and the paths joined by `, `, the tech plugin's first (its base's paths first), each named standard in plugin-line order, `standard-testing` last on `TEST`; `PLUGIN: none` for zero names on `BUILD`.
- **`--labels`** (steps 7 and 10): the same names and checks, but its one stdout line is `LABELS: Technology: <the tech plugin's label, or none> · Used standards: <the standards' labels in plugin-line order, joined by ", ", or none>`, the hand-back's `LABELS:` line as is, with no `PLUGIN` line; the same exit codes.
- **Developer:** each named plugin's `<plugin>/references/*-template.md` files are added to its paths, so its templates arrive with its rules.
- **Reviewer** (once `code-reviewer` exists, #64): each plugin's `<plugin>/references/development.md` becomes `<plugin>/references/review.md`, and a `review.md` that isn't a readable file (symlinks followed) is dropped, since the hook denies a missing file.
- **Exit codes:** 0 the line printed; 2 usage error only; 3 a name or mode problem (one stderr line each, nothing on stdout), a template file name the line can't carry (a comma or a control character), invalid plugins reported by `list-plugins.sh` (its stderr printed), or a listing `list-plugins.sh` reports TRUNCATED (its stderr printed); 4 `list-plugins.sh` missing; 5 a required tool missing, an awk failure, or no temp file could be made; 6 `list-plugins.sh` failed with an exit other than 0, 1 or 3, such as 2 (skills folder missing or unreadable), its stderr printed, then `list-plugins.sh failed (exit N); expected exit 0, 1 or 3; …`; 129, 130 or 143 stopped by HUP, INT or TERM, the temp file removed. A `list-plugins.sh` exit 1 (no plugin) still gives an empty listing.
- **Dependencies:** POSIX `sh`, `awk`, `cat`, `mktemp` and `rm`, checked at start; no `jq`.
- **Side effects:** one temp file for `list-plugins.sh`'s stderr, removed on exit; it writes nothing else.
- **Runtime:** about 74 ms, nearly all of it the `list-plugins.sh` run; measured on macOS, average of 5 runs.

## `scripts/inject-plugins.sh` (the hook)

A `PreToolUse` hook on `Agent`, registered in the global `settings.json` (its entry and the injected block shape: the hook contract, which SKILL.md's Scripts section points to). Claude Code runs it, never the main thread.

- **Command:** registered as `sh "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/procedure-agent-initialization/scripts/inject-plugins.sh"`, reading one hook input on stdin; `--help` (or `-h`) prints its contract and exits 0.
- **Acts on:** an `Agent` call whose `subagent_type` is `code-developer` or `code-reviewer`. The list is fixed in the script; an agent that starts loading plugins needs a script change. Every other call gets no output and passes unchanged, unless stdin is unreadable (below).
- **Checks, per `PLUGIN` path:** absolute; no `..` segment; under the skills folder, compared as text; in a `tech-*` or `standard-*` folder whose `SKILL.md` frontmatter has `name:` equal to the folder and `disable-model-invocation: true`; that `SKILL.md` or a file under its `references/`; a readable regular file; resolving, symlinks followed, inside the real path of its plugin folder (the folder itself may be a symlink); holding none of the tokens Claude Code expands in a skill (its `--help` lists them) or the brief's closing line (`A marked gap beats a papered-over one:`). Once the path checks pass, each file is copied once into a private temp folder; the plugin test is re-run on each `SKILL.md` copy, and the token, closing-line and frontmatter scan and the injection all read those copies, so the checked bytes are the injected bytes (a problem is still named by the original path).
- **Allow:** stdout is one JSON line, `permissionDecision: "allow"` with `updatedInput`: the call's input with the prompt followed by one block per plugin, in `PLUGIN` order, one empty line between a block's files and between blocks. The allow also approves the `Agent` call itself, so no permission prompt is shown for a dispatch that passed every check.
- **Deny:** stdout is one JSON line, `permissionDecision: "deny"`, with a reason that always starts `procedure-agent-initialization:`. A path problem reads `procedure-agent-initialization: PLUGIN <problem>: <path>[; PLUGIN …]. <hint>`, the hint naming `render-plugin-line.sh` and SKILL.md's step 9 as the way to rebuild the line; a folder that fails the plugin test reads `not a plugin (<why>)`, and a file whose real path leaves its plugin folder reads `file resolves outside its plugin folder <real folder> (to <real file>)`. The agent doesn't start; the main thread receives `PreToolUse:Agent hook error: <reason>` (step 9).
- **Denied for a listed agent:** a `PLUGIN` line that is missing, empty or holds a control character, a plugin whose first path isn't its `SKILL.md` or whose paths are split into two runs, any failed check, a missing `jq`, a `jq` or `awk` failure, or the script stopping before it decides (fails closed). Every other agent passes when `jq` is missing or fails, except when `jq` can't read the input and its `subagent_type` value holds an escape (a backslash): the agent can't be known without decoding it, so it is denied. The text match without `jq` catches a listed name and the `subagent_type` key in every JSON spelling (each character literal or `\u00HH`, either hex case).
- **Unreadable stdin denies every `Agent` call,** listed or not, since the agent is unknown.
- **No output:** `PLUGIN: none`, or not a listed agent.
- **Exit codes:** 0 for every hook decision (read stdout); 2 a usage error (an unknown option).
- **Dependencies:** POSIX `sh`, `awk`, `cat`, `mktemp`, `readlink` and `rm`, in every macOS and Linux base system; jq 1.6+ (`--rawfile`), whose version SKILL.md step 1's checklist shows. A missing `jq` denies every listed dispatch.
- **Side effects:** a private temp folder (`mktemp -d`) holding the file copies, removed on exit, a HUP, INT or TERM included (a TERM mid-run still denies a listed agent); an unwritable `TMPDIR` denies with the `mktemp` reason. Otherwise it writes only its decision to stdout and never edits a file, a setting or the brief's other fields.
- **Runtime:** about 14 ms for a not-listed agent, 155 ms for 14 plugin files, measured on macOS with jq 1.8.1, average of 5 runs; the entry's `timeout` is set in the hook contract.
- **Fails open on a timeout or a hook error:** Claude Code then lets the dispatch through unchanged, with no plugins (SKILL.md's Gotchas).
